# Resolve the workflow

Use installed skills discovered by the host. Resolve the public name first unless the user or project selects a particular version. Use the earlier local name if that is the available equivalent. Invoking a skill still requires its host tools to be connected for the requested operation.

| Work needed | Public skill ID | Earlier local ID |
| --- | --- | --- |
| Retrieve or maintain project knowledge | `atlas-notes` | `atlas-knowledge` |
| Deliver OutSystems 11 features | `forge-outsystems-11` | `forge-o11` |
| Deliver Blender assets | `blender-production` | Same |
| Narrow retrieval and verification output | `tokenwise` | `token-efficiency` |

A custom installed workflow can participate if its scope matches. Give it the relevant packet, follow its tool requirements, and collect its observed results. A companion workflow returns control without starting the coordinator again.

When Atlas is unavailable, use the supplied brief and the project’s existing source search. When a delivery specialist or required tool is unavailable, preserve the delivery gap and continue any independent checks or preparation within scope. When Tokenwise is unavailable, read the narrowest sources the task calls for. A missing skill does not authorize extra setup or expand the task scope.
